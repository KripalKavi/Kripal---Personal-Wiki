# First 10% Is Free

## Definition

In the AI era, the first 10% of any project — directional concept, scaffold, prototype, first-pass draft — is essentially free. The structural cost of *starting* has collapsed. But the last 10% is still 90%: getting from working-demo to ship-quality remains where the actual expertise lives.

[Max Schoening](../entities/max-schoening.md):

> "I think the first 10% of every project are now free. That's how I would describe it... There's no point in writing a PRD if you can just do the janky version and do the 'here's the demo of what I think we should build.'"

> "If you look at a lot of the... it takes almost no effort to now build the first version of a startup or the first version 0.8. And then I think the last — or maybe even if you're generous and say the first 90% are now done — the last 10% are still actually 90%. That's always the hardest."

---

## Why It Matters

Three structural consequences:

### 1. The Bottleneck Moves to Judgment

If starting is free, the differentiator is no longer *can you start* but *will you start, with conviction, in the right direction.* This is why [Cultivating Agency](../concepts/cultivating-agency.md) is now load-bearing. Skill barriers used to gate action; AI dissolved them; what's left is the disposition to act.

### 2. The Bar for "I Tried" Rises

A working prototype used to be evidence of differentiated execution. It isn't anymore — anyone can produce one in a weekend. Showing up with a demo is now the new baseline, not the new moat. Reviews and promo cases need to recalibrate around the **middle 80%**: the slog from demo to shippable, the consolidation, the obviously-good polish.

### 3. Concurrent Exploration Becomes the Default

Schoening: *"It's cheaper to just explore a lot of paths. You can now afford to say I'm going to send off 10 agents to explore 10 different things and then see if I was right."* The shape of work shifts from sequential (commit to one direction, build it) to parallel (try ten, prune fast). This compounds with the [Tiny Core](../concepts/tiny-core.md) principle: more shots on goal at finding the right tiny core.

---

## "Demos Not Memos"

Schoening's GitHub-era principle, brought to Notion:

> "We used to say this at GitHub in our product reviews a lot, which is demos not memos. And then we would say, 'give me something to react to' — which is, okay, if you're going to write a PRD, just write the change log or the blog post that a user would read. Now, it's much easier to give people something to react to."

The implication: written specs were always a poor substitute for the actual product. When the actual product is free to produce, the spec becomes redundant — and worse, it becomes a delay tactic.

This also breaks the waterfall model: *"Waterfall is sort of — why bother?"* Iteration is now built into the front of the process, not bolted onto the end.

---

## The Asymmetric Distribution

A non-obvious consequence: if the first 10% is free but the last 10% is still 90%, then **the distribution of skill required across a project has flipped.** Early-stage work used to require expertise (writing the spec, scoping correctly, prototyping). Now it requires only judgment about *direction*. Late-stage work used to be hands-the-crank execution. Now it's the entire residual of where expertise lives — reliability, performance, edge cases, polish, "obviously good" craft.

This is why Schoening's *"vibe coding hasn't improved software quality"* observation matters. The free first 10% has flooded the world with demos; the last 10% has not been democratized; the gap is where craft now lives.

## PM Application

For a Senior Director of PM at Microsoft:

1. **Reform performance reviews around the middle 80%.** "I built a prototype" is the new baseline. The promo case question is what happened in the slog: consolidation work, reliability hardening, polishing toward obviously good. The PM who produced a demo and stopped should not be rewarded for the demo.

2. **Kill PRD-as-deliverable.** A PRD as an artifact someone reviews and approves is now redundant. Replace it with the working prototype + the user-visible change log / blog post. The PRD-replacement is *the thing that gets shipped*, not a description of it. Schoening's *"demos not memos."* This shifts the review gate from text to artifact and accelerates iteration.

3. **Increase concurrent exploration explicitly.** If each spike now costs an afternoon, why does Microsoft typically run one product spike at a time? Sanction running 5–10 parallel explorations per question. The review gate becomes which to *kill*, not which to *fund*. Calibrate the team's psychological model accordingly — most explorations should die.

4. **Recognize the craft gap as the new moat.** The middle 80% and the last 10% are now where Microsoft can outcompete AI-flooded competitors. M365's reliability, scalability, enterprise integration, edge-case handling, accessibility — these are the parts of software that AI does not generate for free. Position investment here, not in another demo-quality feature.

5. **Audit Copilot surfaces for "demo quality, not ship quality."** Many AI features across the industry (and inside Microsoft) are stuck at 0.8 — convincing demo, unreliable production. Internal challenge: *which Copilot features have not graduated through the last 10%?* They are dragging the brand. Triage: ship-quality them or kill them.

6. **The Eric Lou model becomes hiring guidance.** When a candidate's portfolio is "I built X working prototype," that is no longer differentiated. Probe: *what was the middle 80% on this project? What did you have to make obviously good?* The answer separates skilled-but-demo-only operators from real builders.
