# Steering vs. Rowing

## Definition

Steering vs. rowing is the distinction between directing a system and manually doing its work. In an AI-heavy workflow, the human's value shifts from producing every artifact to setting direction, constraints, and intervention points while the system executes.

## Why It Matters

AI raises the leverage of good judgment and lowers the value of repetitive execution. That changes the unit of work:

- Rowing is typing the memo, assembling the deck, filing the ticket, or manually moving each step through the process.
- Steering is deciding the goal, defining the constraints, reviewing the output, and correcting course when the system drifts.

The more capable the system becomes, the more valuable it is to keep the human at the steering layer and the model at the rowing layer.

The transcript also pushes this one step further: steering is no longer just a human-plus-model loop. As agents become more persistent, steering starts to happen across people, agents, and shared workspaces at the same time.

## Examples

- A PM gives an agent the objective, quality bar, and edge cases, then reviews the result instead of drafting every artifact from scratch.
- A manager uses AI to draft status, summarize work, or propose options, then spends time on judgment and alignment.
- A product team designs a workflow where the user returns to steer the system rather than re-entering the same context on every visit.
- A team collaborates through shared agent output instead of passing screenshots of local runs back and forth in Slack.

## PM Application

For Microsoft product teams:

1. **Design for steering moments.** The UI should make direction-setting, review, and correction fast and obvious.
2. **Keep state durable.** If the user has to row from scratch every time, the product is missing the point.
3. **Instrument judgment.** Measure whether the system is helping users make better decisions, not just produce more output.
4. **Use thin scaffolding.** Build only the amount of structure needed for today's models, then remove it as capability rises.
5. **Make writing part of steering.** Good docs should compress uncertainty into a sharper hypothesis, not just preserve history.
